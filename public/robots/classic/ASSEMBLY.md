# Original character assembly

These SVGs reconstruct eight standing player views and the standing captain and scientist from the official character skeleton and equipment. The original vector paths are retained. No Flash bytecode is executed, and no replacement character art is drawn.

The previous compositor appended every equipment part after the body. That put the captain's foot equipment over his chest and face, and let default foot components overlap the player's waist. The original `empty_body` display list puts `foot` behind `color`; `ClothPreview.changeDeep` then reorders upper slots for each direction. The reconstruction preserves that behavior rather than using equipment ID order as paint order.

The direction-labelled outer frames are `down` 1, `leftdown` 8, `left` 16, `leftup` 24, `up` 32, `rightup` 40, `right` 48 and `rightdown` 56. Frame 8 is therefore a valid direction selector. The nested movement clips are explicitly rendered at frame 1, matching `SkeletonClothPreview.stop()` and `ChangeClothAction.goOver()`. These files contain standing poses; walking presentation is handled separately by the application.

`build_classic_robots.py` reads the original cached SWF XML, replays placements and removals through the selected frame, and recursively reconstructs each nested display list using its complete six-value MATRIX. Scale and skew are preserved, and translations are converted from twips to logical pixels. Cached FFDec exports supply only the immutable leaf shape paths and gradient definitions; their export-only normalization groups and rounded placement matrices are not used to register equipment.

For example, the captain's left-front foot clip places its two copies of symbol 5 at matrices `(0.9020386, 0, 0, 0.9020386, 21.2, 14.5)` and `(1, 0, 0, 1, 6.5, 19.45)`. Both transformations are retained. The source NPC model applies a uniform 1.4 scale to the composed body, and the source NPC configuration supplies each role's colour and equipment IDs. The common player viewport is measured from the union of all eight reconstructed silhouettes. NPC viewports are measured separately with offline librsvg. Every viewport retains two logical units of padding.

`manifest.json` records the official UI and equipment URLs, source and output hashes, source display-list and skeleton-script hashes, direction labels, standing frames, slot registrations, original render orders, measured bounds, and placement counts. Full per-asset placement matrices are saved in the ignored `.cache/classic-robots/assembly-audit/placements.json`; the public manifest records that audit's path and hash. The source workspace is the ignored `.cache/classic-robots/`, including `UI.xml`, item XML files, skeleton scripts and the existing leaf SVG exports. Rebuilding requires Pillow and `rsvg-convert`. If an item XML export is missing, create it from its cached SWF with FFDec's `-swf2xml` command before rebuilding.

Focused offline verification checked all ten composites for source-derived slot order, matching output hashes, complete alpha padding and a shared player viewport. The captain's individual foot matrices were compared with the original display list, and individual standing views were visually reviewed. The offline contact sheet and individual renders are saved under `.cache/classic-robots/assembly-audit/`. These checks establish the vector assembly; the application renderer, stylesheet, caching and in-app presentation are verified separately.
