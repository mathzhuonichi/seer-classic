# Official Seer attribute artwork

The attribute symbols in this directory are original vector button artwork from the official [UI.swf](https://seer.61.com/dll/UI.swf). Each file preserves the normal `up` state of its `Icon_PetType_<id>` button. No substitute symbols were drawn, and the original paths, colours and gradients were retained. Only export metadata was removed and a matching SVG viewBox was added.

The Chinese-name/type-ID mapping comes from `SkillXMLInfo_typeClass`, embedded binary character 149 in the decoded official [RobotCoreDLL.swf](https://seer.61.com/dll/RobotCoreDLL.swf). The source `SkillXMLInfo` class reads that embedded XML to resolve Chinese type names. The source `UIManager.getButton` resolves `Icon_PetType_<id>` and obtains its tooltip label from `SkillXMLInfo.petTypeNameCN`; `NormalSkillBtn.init` uses those same symbols for skill cards and selects `Icon_PetType_prop` for attribute-category skills.

All 18 types present in the recovered species and skill catalog have original artwork here. The additional original 远古 and 自然 symbols and the generic attribute-skill symbol are also retained, giving 21 single-type and generic files. The 28 original composite buttons needed by the 217 dual-type species are also exported, for 50 physical SVG assets in total after including the additional 邪灵神秘 composite needed by three skills. The important IDs include 次元 17 and 邪灵 19; ID 18 is 远古. This mapping is taken from the embedded source table rather than inferred from icon order or appearance. `manifest.json` records the official source URLs and hashes, decoded-core and embedded-XML hashes, original class names, button character IDs, state, dimensions and output hashes. No required single type or catalog dual pair is missing. Each composite is the original combined `Icon_PetType_<id>` button from the UI source, rather than a local juxtaposition of two single icons. The pair mapping uses the original `att` component IDs in the embedded type table; original Chinese order can differ from catalog order (for example, type 47 is 战斗 火). The manifest retains each composite’s original spaced Chinese name, English name, component IDs and Chinese component names, alongside its existing provenance fields. The 217 dual-type species use 28 pairs. The 294 dual-type skills use 29 pairs: skills 11660, 11661 and 11662 additionally require type 62, 邪灵 神秘 (`att="19 14"`, `en="demon_myth"`). Its original `Icon_PetType_62` button is also exported, so the assets cover both catalogs with 29 composite symbols. Other later pairs present in the current source table are outside this catalog scope.

The ignored `.cache/type-symbols/` holds the raw button exports and offline visual-review renders. Source files and the embedded mapping are in `.cache/classic-robots/`. JPEXS FFDec 26.3.0 exports the original buttons with `-selectid <comma-separated-button-character-ids> -format button:svg -export button <output-directory> <UI.swf>`. The retained file is each selected button's `1_up.svg`. The official tool's [command-line documentation](https://github.com/jindrapetrik/jpexs-decompiler/wiki/Commandline-arguments) describes button SVG export.

`src/presentation/type-icon-assets.json` is the small runtime projection of `manifest.json`: single-type entries retain `path` and `sha256`; composite entries also carry `name` (the compact official Chinese name), `types` (official Chinese component order), and `typeId`. Reverse-order compact Chinese keys are aliases to the same composite entry, using `manifest.aliases`; no second image is generated. Regenerate the projection from `manifest.icons` and apply `manifest.aliases` whenever the exported artwork or manifest changes. For example, 战斗火 and 火战斗 both resolve to type 47, with canonical `name: "战斗火"` and `types: ["战斗", "火"]`. `TypeIcon` imports that source-tree projection, avoiding Vite imports from the public directory; the complete public manifest remains the provenance record.

`TypeIcon` uses these source assets without an invented recolour, ring or alternative icon design. Unknown types are displayed as text rather than assigned an incorrect 普通 symbol. Its Chinese tooltip is an immediate styled portal under `document.body`, using fixed positioning to escape clipping in skill cards and other panels. Native title attributes and the help cursor were removed. Standalone icons support keyboard focus; enclosing skill buttons supply their own focus, and callers can explicitly use `focusable={false}`. For a grass icon the accessible label and tooltip are exactly 草属性.

Focused validation checked the complete 18-type catalog mapping, the 217 dual-species / 28-pair mapping and the additional skill-only type 62 in both component orders, all output hashes, nonempty offline SVG renders, and representative single and composite source designs. Ignored raw dual exports and their contact sheet are under `.cache/type-symbols/duals/` and `.cache/type-symbols/dual-review/`. TypeScript compilation was checked separately. Application hover/focus and card-clipping behavior are verified through the central in-app browser workflow.
