# Official PetBag layout integration

## Reference and layout

The actual recovered `PetBagPanel_UI` display list, symbol 812 of official `UI.swf`, was inspected before rebuilding the creature window. Its composition has staggered icon navigation at the far left, a dedicated central portrait projector, four tabs above a navy detail well on the right, and a lower region for dynamic party controls. The previous vertical party roster and profile form did not reproduce that arrangement.

The new `official-petbag` presentation follows those regions. Eight staggered navigation positions expose lead selection, recovery, warehouse access, party deposit or admission, position exchange, skill editing, learning-value editing, and experience allocation. A persistent portrait uses the recovered projector. Four primary tabs read Information, Ability, Items, and Profile in Chinese; ability and skill editing share the Ability region. Six ordered party slots remain visible across the bottom. Warehouse browsing opens an overlay within the window, retaining name, nickname, number, and attribute filtering and bounded eight-item pagination.

The interface uses the actual clean source frame, symbol 735, including its correct title, empty hexagonal navigation pads, projector, and detail well. Native controls align its original geometry: the portrait begins at (17.2%, 13.1%) with size (28.1%, 59.6%), and the right region at (46.6%, 13.1%) with size (49.7%, 59.6%). Source symbol 45 supplies the six party-slot frames. Eight isolated original icons occupy the eight navigation positions. The four recovered labeled tab images match the four real native tab controls. The standalone window preserves the frame's recovered 647:471 aspect ratio and native 647-pixel width, fitting smaller hosts without stretching. The shared title remains accessible but is visually hidden because the original frame already includes its own title. The header retains dragging and the original close button. Active/hover tabs preserve their calibrated image sizing, overriding the older generic hover background shorthand. No inert screenshot substitutes for a working button. Source assets and extraction details are recorded in `public/ui/classic/petbag/manifest.json` and the main classic manifest. The recovered source font remains available for dynamic content.

## Behavior and scope

The externally selected UID and `onSelect` callback remain authoritative. Party ordering, active-battle switching, party admission and deposit constraints, position exchange, healing, and their existing dispatch actions are retained. Skill replacement, nickname editing, experience allocation, evolution, item use, and validated learning-value editing retain their previous mechanics. No game engine or save code changes are made.

`Raising` receives optional presentation and tab-request props for the new parent. Existing callers retain the prior default presentation and four tabs. PetBag CSS rules are scoped to `.official-petbag`; prior global management styles remain in place for inventory, encyclopedia, and other windows.

Browser inspection found that the projector's available portrait area was rectangular, while the alpha-bound placement helper assumes a square stage. The selected portrait now uses a centered square with side equal to the smaller available dimension. Its `CreatureArt` call disables the evolution-stage size multiplier and centers the visible alpha bounds, so infant portraits occupy the same useful presentation area as mature portraits without image distortion. These new optional component props retain the previous defaults for every other caller; world creatures, battle portraits, and party cards are unaffected.

## Verification boundary

`npx tsc --noEmit` passes after the layout and navigation changes. Source inspection confirms the original dispatch actions and selected-UID propagation. The parent's isolated browser checks pass for warehouse paging/search, admission/deposit, lead selection, position exchange, healing, learning-value saving, nickname and pooled experience, skill replacement, the original frame ratio and all eight control positions. Active-battle presentation was preserved by source inspection but was not newly exercised in this visual revision. See `graphical-management-integration-v28.md` for actual evidence and limits. This change produces no production build, package, or commit.
